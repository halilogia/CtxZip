# Technical Notes and Verified Observations

## Verified

- `summary-validity` / `ozet-gecerlilik` records explicit repository-relative tracked files and a clean Git HEAD for an existing Chapter/Volume. Synthetic Git tests verify localized CLI use, rejection of dirty repositories and untracked/unsafe paths, exact changed-path stale detection, and preservation of both body text and a manual-edit marker. It does not infer every file a summary claim depends on. After this addition the full suite passes 197 tests; `compileall`, CLI help, and `git diff --check` pass.
- On 2026-09-26, ChatGPT turn events leave `record_index` empty rather than report the derived turn ordinal; parser version 2 stores active mapping-node keys in `record_ids` and hashes the same bytes it parses. Event snapshot schema v2 stores those IDs, while schema v1 snapshots remain resolvable. Synthetic fixtures verify archive round-tripping. The full suite passes 197 tests; real export compatibility remains unverified.
- Recent raw-turn context now selects provider-neutral `TURN_TRANSCRIPT` events. ChatGPT uses its native source-linked turn events; Claude/Codex adapt their existing parsed turn text through the compatibility bridge. The production context regression retains chapter coverage and output behavior, and a focused unit test proves event text is the selected context content.
- When Claude private-thinking inclusion is explicitly enabled, recent-context generation takes the legacy direct path so private reasoning is not wrapped into canonical events; a regression checks this boundary.

- On 2026-09-26, `parse_claude_session` and `parse_codex_session` were verified to reject a source file changed between source-hash capture and parse completion. The regression test simulates a concurrent source update for both providers. The full suite passes 186 tests; `compileall`, `ctxzip.py --help`, and `git diff --check` also pass. This check detects persistent changes across the parse window; it does not lock the file against writers.
- The application uses the Python 3.10+ standard library; the CLI is in `ctxzip.py`. Source parsers, chapter/volume orchestration, state files, privacy cleanup, LLM submission, and Git copy checks live in `ctxzip_core/` modules.
- On 2026-09-25, CLI smoke tests for `--help`, `collect`, `transcript`, `status`, and manual summarization ran with Windows/Python 3.12. Project-specific archive names and counts are intentionally omitted. These checks do not verify summary quality or a live LLM connection.
- `raw/` contains the current source copy. Before any changed JSONL source replaces it, the previous bytes are atomically copied to a content-hash-derived `*.onceki.jsonl` sibling. Repeated identical prior versions reuse the same path; the regular session listing excludes these history files.
- `source_collection.find_source_version()` resolves a matching active JSONL/ChatGPT file or retained JSONL history file by provider ID, session ID, and full SHA-256, validating file contents and rejecting traversal-style identifiers. It returns no path when that exact raw version is unavailable. Parsed event snapshots are retained separately by source hash and parser-version digest under the private `.ctxzip-events/versions/` directory.
- `BAGLAM.md` selects completed summaries only and uses an approximate token budget. With no query inputs selection retains the legacy recency order; optional task/file/commit inputs use deterministic lexical ranking.
- The final LLM submission boundary redacts known patterns again and displays the full prompt and destination. No request is sent without interactive approval; `--onayli-gonder` deliberately bypasses this approval.
- Git index checks run automatically only in clones where the hook is installed. Git hooks are not transferred with the repository and can be bypassed with `--no-verify`.
- Parser code is split into `parser_common.py` and provider modules for Claude, Codex, Antigravity, and manual input; `parsers.py` remains a facade for legacy import paths.
- `source_freshness.py` reconstructs the exact sanitized Chapter source hash using the recorded source language. New Chapter metadata also records the source adapter version; bump a provider's `PARSER_VERSION` when normalized turn interpretation changes. Context generation excludes unedited summaries when the adapter version or readable source hash changes, or a shortened source no longer covers the recorded range; containing Volumes are skipped and unaffected Chapters are considered individually. Verified manual body edits remain explicit overrides and are neither excluded nor modified. Missing legacy source hash/language metadata and unavailable or empty parser output leave content freshness unknown; if only parser-version metadata is missing, an available source hash is still compared, but version freshness remains unknown. Persistent stale status and summary file/path validity remain open; metadata-less or contradictory orphan reconciliation remains open; consistent non-sequential orphans are recovered. Fully covered source ranges in the same session are excluded after ranking; partial-overlap and manually edited summaries remain eligible, and incomplete provenance is not guessed.
- Fault-injection tests cover chapter/volume state writes, partial collect copy batches, partial transcript batches, and a later project's LLM failure after an earlier project completed. Retries reuse deterministic filenames, finish missing outputs, and do not duplicate persisted chapters/volumes. Separate subprocess tests exercise abrupt exits before atomic replacement, after Chapter output, and between event/transcript writes. A schema-backed summary journal is not justified by the demonstrated failures: metadata-backed deterministic reconciliation handles persisted summaries; a prompt-only interruption is handled by preserving the existing prompt. Power-loss durability, cross-process coordination, and broader legacy reconciliation remain unverified.
- `doctor` performs read-only settings shape, Python, parser/capability/version registry, configured source-root accessibility, locale, archive parent writability, LLM configuration, Git repository, and installed-hook checks. It never creates the archive or contacts the configured endpoint and outputs only whether an API-key environment variable is present. It does not inspect external tool executable versions or verify provider connectivity.

## Unknowns

- A request to a locally configured LLM endpoint's `/v1/models` route timed out. Live LLM summarization has not been verified.
- Claude Code and Codex JSONL fields may vary across versions. The Antigravity `brain/` path does not provide full chat history.
- `len(text)/3.5` is not an actual token count; the secret-pattern cleaner cannot find every secret.
- ChatGPT `conversations.json` import is verified only against a sanitized synthetic `mapping`/`current_node` fixture. The original remains unchanged in `gelen/`; each conversation becomes a derived `raw/chatgpt/` record, and only active-branch textual parts are parsed. Real sanitized export and schema/version compatibility remain unverified.
- Claude/Codex event parsers hash source files before and after parsing and reject a changed hash. This catches ordinary persistent concurrent writes but does not bind parsed records to one immutable byte snapshot if the source changes and is restored between checks; a hashed temporary snapshot would be needed for that stronger guarantee.

## Principles

Do not put raw archives, settings, or context packs in the public repository. Re-verify test or behavior claims from summaries against the current commit and test output. Test new source formats with real examples sanitized of personal data.
