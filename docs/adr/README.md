# Architecture decision records

This directory records accepted decisions that constrain architecture or compatibility. ADRs explain why the current design exists; `ARCHITECTURE.md` describes how the implementation currently works.

Use the next zero-padded number for new records. Keep accepted records immutable in intent: when a decision changes, add a new ADR that links to the record it supersedes instead of silently rewriting history.

The initial records document current, verifiable project contracts. Their recorded dates do not imply that a formal review occurred on that date.
