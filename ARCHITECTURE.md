# Architecture

CtxZip is a CLI application that uses the Python 3.10+ standard library. `ctxzip.py` manages commands and data flow; security and external-system boundaries live in `ctxzip_core/`.

```text
source discovery → collect → raw/
raw/ → format parsers → dokum/
turns → summarize → bolumler/ → ciltler/
bolumler/ + ciltler/ → context → BAGLAM.md
```

| Layer | Role | Boundary |
| --- | --- | --- |
| `raw/` | Current source copy plus version history | The current copy is refreshed when a session changes; each replaced JSONL version is kept under a content-hash-derived `*.onceki.jsonl` name. May contain sensitive data. |
| `transcripts/` (`dokum/` in existing archives) | Readable Markdown | Tool output is truncated; this does not replace the raw record. |
| `chapters/` (`bolumler/`) | Turn ranges from one session | Includes source-turn and hash metadata; summaries may be wrong. |
| `volumes/` (`ciltler/`) | Higher-level summaries of completed chapters | Detail is progressively lost. |
| `state.json` (`durum.json`) | Processed ranges and chapter/volume relationships | Processing state, not the source conversation. |
| `CONTEXT.md` (`BAGLAM.md`) | New-session context pack | Does not replace code, Git, or tests. |

## Module map

| Module | Responsibility |
| --- | --- |
| `ctxzip.py` | Settings, project selection, CLI commands, and compatibility exports |
| `ctxzip_core/source_collection.py` | Configured source discovery, project mapping, atomic archive copying, incoming-export collection, and hash-based source-version resolution |
| `ctxzip_core/parsers.py` | Parser facade, source selection, current parser-version registry, and Turkish compatibility exports |
| `ctxzip_core/source_capabilities.py` | Declared source-format coverage and adapter limitations |
| `ctxzip_core/parser_common.py` | Shared `Turn` model, JSONL reading, working-directory discovery, and tool summaries |
| `ctxzip_core/parser_claude.py`, `parser_codex.py`, `parser_antigravity.py`, `parser_manual.py` | Provider-specific source format parsers behind the shared turn model |
| `ctxzip_core/parser_chatgpt.py` | Local `conversations.json` export splitting and active-branch text parsing |
| `ctxzip_core/events.py` | Provider-neutral event envelope, stable source-version references, source-change verification, and a compatibility bridge from legacy turns |
| `ctxzip_core/artifacts.py` | Complete-inventory Antigravity tree synchronization with content-addressed prior versions |
| `ctxzip_core/event_store.py` | Atomic current and content-addressed historical event snapshots with exact-reference resolution |
| `ctxzip_core/sessions.py` | Listing archived/incoming sessions, importing supported ChatGPT exports, and generating short session IDs |
| `ctxzip_core/transcripts.py` | Per-project transcript generation, localized formatting, secret cleanup, and event-snapshot persistence |
| `ctxzip_core/text.py` | Shared text cleanup, timestamp formatting, hashing, and approximate token counting |
| `ctxzip_core/chunking.py` | Turn budgeting and chapter chunking |
| `ctxzip_core/summary_store.py` | `durum.json`, summary metadata, body hashes, and manual-edit detection |
| `ctxzip_core/summary_validity.py` | Reviewed summary scope authoring against clean, tracked Git paths and HEAD |
| `ctxzip_core/summary_recovery.py` | Recovery of metadata-backed orphan Chapter/Volume state, including number gaps |
| `ctxzip_core/source_freshness.py` | Reconstructs sanitized Chapter source hashes for read-only freshness checks |
| `ctxzip_core/storage.py` | Atomic text/JSON replacement and metadata-preserving atomic file copies |
| `ctxzip_core/git_state.py` | Read-only branch, HEAD, diff, untracked-file, and worktree fingerprint snapshot |
| `ctxzip_core/diagnostics.py` | Read-only Python, settings, locale, parser registry, path, LLM configuration, Git, and hook checks |
| `ctxzip_core/knowledge.py` | Versioned per-type decision, constraint, test, question, and file-mention records with event provenance |
| `ctxzip_core/knowledge_capture.py` | User-authored CLI record construction with validated event provenance; no automatic extraction |
| `ctxzip_core/test_runner.py` | Explicit local command execution and Git-bound test evidence capture; arguments and output are not persisted |
| `ctxzip_core/retrieval.py` | Deterministic task/file/commit lexical ranking of completed summaries with selection reasons |
| `ctxzip_core/summary_ranges.py` | Derives reliable per-session source-turn coverage for Chapter and Volume candidates |
| `ctxzip_core/evaluation.py` | Precision/recall, stale-context, token-efficiency, source-coverage, overlap, unique-turn, and unattributed-candidate metrics |
| `scripts/evaluate_context_generation.py` | Synthetic end-to-end evaluation through the production context-pack builder: filesystem freshness, knowledge, Git manifest, and budget |
| `scripts/evaluate_provenance.py` | Synthetic manually labeled event/claim attribution metrics plus Git-bound test-evidence freshness checks |
| `scripts/benchmark_retrieval.py` | Synthetic ranking and overlap-filter timing across unattributed, many-session, and single-session candidate layouts |
| `ctxzip_core/recent_context.py` | Canonical turn-transcript events, source-hash provenance, and Chapter-range exclusion |
| `ctxzip_core/context_pack.py` | Versioned, machine-readable JSON metadata block for Markdown context packs |
| `ctxzip_core/context_planner.py` | Fixed-priority-section context planning, priority/balanced approximate budget profiles, and duplicate-key suppression |
| `ctxzip_core/context_generation.py` | Source freshness, evidence selection, context-pack rendering, atomic output, and safe optional copy |
| `ctxzip_core/prompts.py` | Chapter/volume prompts and prompt version |
| `ctxzip_core/i18n.py` | Locale resolution, namespace catalog loading, fallback, named interpolation, and validation (`locales/<locale>/<namespace>.json`) |
| `ctxzip_core/summarizing.py` | Fills pending summaries, creates chapters/volumes, and manages state transitions for one project |
| `ctxzip_core/privacy.py`, `llm.py`, `git_safety.py` | Redaction, approval/network calls, and Git copy boundary |

Dependency direction is `ctxzip.py → ctxzip_core`. `summarizing` uses session/parser, chunking, summary-store, prompt, and LLM modules. Source parsers use `parser_common` and `text`; `sessions → parsers → parser_common`, `source_collection → sessions/parser_common/artifacts/storage`, `transcripts → sessions/parsers/event_store/storage/privacy/i18n`, `context_generation → sessions/parsers/retrieval/knowledge/planner/storage/git_safety`, `chunking → parsers/text`, `summary_store → text`, and `llm → privacy`. Core modules do not import the CLI; a static import-graph test checks for cycles. Older helper names are compatibility aliases on the facade and CLI. Tests mock LLM calls at the `ctxzip_core.summarizing.call_llm` boundary.

The CLI selects projects and calls `summarize_project`. If a chapter LLM call fails, the core returns `False` and the command stops instead of continuing to other projects, matching prior behavior. Summary files are atomically written before state persistence and metadata-backed orphans are reconciled on retry. Manual prompts are created only when absent, so edits survive an interruption before the matching summary file is written. This is per-file crash recovery, not a multi-file transaction or power-loss durability guarantee; no separate processing journal is currently warranted by the tested failure cases. Write ordering, file formats, and turn numbering are preserved. English names are primary in the Python API; older Turkish names remain compatibility aliases. Turkish on-disk directory names, JSON keys, and summary metadata remain unchanged to preserve existing user archives.

The optional ChatGPT import reads extracted `conversations.json` or numbered `conversations-N.json` files from a project's `gelen/` directory during `collect`. It validates the whole JSON container before writing per-conversation JSON snapshots under `raw/chatgpt/`; IDs become opaque SHA-256 filename keys. The original export stays byte-for-byte in `gelen/`. The adapter follows only the chain from `current_node` through `parent` links and converts string text parts; inactive branches, attachments, and tool structure are not represented. Current coverage is synthetic until a real sanitized export validates the observed schema. ZIP extraction stays a manual user step.

`context_generation.py` adapts completed Chapter/Volume files into `SummaryCandidate` values and delegates ranking to `retrieval.py`. `summary_ranges.py` attaches source-turn coverage from archive state; after ranking, a lower-ranked candidate is excluded only when higher-ranked candidates collectively cover its full range in the same session. Partial overlaps remain eligible to preserve unique turns, and manually edited summaries remain explicit user overrides. `--explain` identifies each exclusion and the higher-ranked summary that covers it. Candidates without complete range provenance remain eligible. Exact normalized file, symbol, changed-worktree-path, and commit matches score above lexical task-term overlap; a freshness penalty applies to candidates explicitly marked stale in metadata. A changed path that exactly matches a path explicitly mentioned in a summary body/title or its file metadata marks that summary `possibly-stale` for this pack; the output title shows the label and no summary file is modified. Summary frontmatter may also declare validity_paths and validity_head_sha; a changed declared path or different current HEAD marks the summary possibly stale. The `summary-validity` command records user-reviewed tracked paths and a clean Git HEAD while preserving the summary body; it does not infer complete claim scope. Input order is the deterministic recency tie-breaker. `--from-git-diff` supplies the current working-tree snapshot. When a task/query, Git snapshot, or private `knowledge/` collection is present, `context_generation.py` composes a priority-ordered plan: task, constraints, decisions, Git state, tests, files/symbols, summaries, recent unsummarized raw turns selected from canonical `TURN_TRANSCRIPT` events (bridged from legacy turn parsers where needed; Claude private-thinking opt-in uses its direct legacy path), open tasks, and questions. `context_planner.py` packs items under the approximate budget, skips items that do not fit, and carries their source references into the output. Generated `BAGLAM.md` begins with a versioned JSON metadata comment containing the project label, generation time, locale, budget/profile, estimated selected tokens, optional branch/HEAD/worktree fingerprint, and source references. `ctxzip_core/context_pack.py` validates this contract; the human-readable Markdown remains the body. The English `CONTEXT.md` name is reserved/ignored for a later compatibility-aware output migration. The default `priority` profile keeps one shared cap; the opt-in `balanced` profile applies proportional category caps, fills its recent-raw reserve with up to 20 latest turns not covered by current Chapter ranges, and withholds the safety reserve. `source_freshness.py` recreates a Chapter's sanitized source hash from its recorded turns, using the language recorded when that hash was created so changing the CLI locale does not create a false mismatch. Parser adapters publish versions through `parsers.py`; increment a provider's `PARSER_VERSION` when its interpretation or normalized turn text changes. A recorded/current version mismatch, changed source hash, or readable current session that no longer covers the full recorded range excludes that unedited Chapter and any containing Volume from context without modifying either summary file; unaffected Chapters in the Volume become candidates individually. Chapters whose body hash proves a manual edit are retained as explicit user overrides. Balanced mode can then include the changed source turns because stale, unedited Chapter ranges no longer count as coverage. Missing legacy hashes/language/parser-version metadata and unavailable/empty parsed sources remain unknown and are not automatically invalidated. Test evidence without an exact matching snapshot is labeled stale or unknown. File mentions whose exact path changed in the current worktree are labeled possibly stale; other mentions remain unknown because they lack a recorded Git baseline. Decisions and constraints may carry optional repository-relative validity paths and a Git HEAD baseline. They are current only when the baseline HEAD matches and none of those paths changed; a different HEAD or matching dirty path marks them possibly stale, while absent scope/baseline remains unknown. `--explain` reports ranking signals and candidates omitted by budget. With the default `priority` profile and no effective query or structured knowledge, legacy recency selection and chronological output are preserved unless a source-turn range is fully covered by higher-ranked summaries.

`evaluation.py` compares task-aware ordering with the legacy recency order on a sanitized twelve-case fixture dataset. The JSON report retains ranking-only regression metrics and adds `planned_context` results after production ranking, full-range overlap exclusion, and `context_planner.plan_context()` budget packing. It reports Precision@K, Recall@K, stale-context rate, token efficiency, relevant-source coverage, irrelevant selected-item counts, selected/omitted IDs, and packed token estimates. Overlap metrics include unique turns, duplicate turn instances, and candidates without source-range provenance before/after filtering. Two synthetic cases received blind second-reader relevance review; an unanswerable query measures irrelevant inclusions. An optional fixed-item fixture measures how task/constraint context competes for the budget. Run `python scripts/evaluate_retrieval.py` to print the per-case JSON report. These cases are regressions, not a representative quality benchmark. The harness does not exercise filesystem-based stale-source filtering or the full structured-knowledge context assembly.

Run `python scripts/evaluate_provenance.py` for a separate, explicitly synthetic manual-label regression. It compares parser-emitted event references to expected source record/turn/kind labels, measures support and citation quality for hand-labeled summary claims (including one unsupported claim and misattributed reference), and checks current/stale/unknown Git-bound test evidence through the production freshness function. This checks the evaluator and a few known behaviors; it is neither a real summary-quality benchmark nor representative source/commit attribution evidence.

Run `python scripts/benchmark_retrieval.py --sizes 100 1000 5000 --repeats 3` for synthetic ranking and overlap-filter timings. On one Windows run with Python 3.12.14 and 5,000 candidates, ranking took roughly 35–39 ms; overlap filtering took 0.4 ms with missing provenance, 11.2 ms across many sessions, and 21.3 ms in one session. These are machine-specific in-memory timings and do not model file I/O, memory use, or real archive distributions; use them to guide profiling, not to justify an index migration.

Legacy Chapters without `parser_version` can still be source-hash checked when `kaynak_hash` and `source_language` are present; parser-version freshness itself remains unknown.

`events.py` defines immutable event envelopes with deterministic IDs and source references containing source ID, session ID, source SHA-256, parser version, turn number, and an optional source-record index, and zero or more source record IDs. ChatGPT currently emits one transcript event per turn; its record index is deliberately empty because one turn can merge multiple source mapping nodes. The event retains active mapping-node keys in `record_ids`; compatibility with real sanitized exports remains unverified. Claude Code and Codex now expose additive parsed-session APIs that emit granular user/assistant messages, tool-call summaries, supported metadata, and limited tool results. These parsers hash the source before and after parsing and reject results when the observed hashes differ. This detects persistent changes during parsing but is not a strict immutable snapshot: a source changed and restored between checks could evade detection. The existing `parse_*_turns` functions remain the compatibility path and keep transcript output unchanged. Claude private thinking is never copied into canonical events; Codex reasoning summaries are included only when the existing opt-in is enabled. Antigravity Markdown artifacts emit one generic transcript event per artifact; manual imports emit one generic transcript event per file. These wrappers intentionally do not infer message roles, tools, timestamps, or full conversation structure. `write_transcripts` stores normalized events under the private `.ctxzip-events/` directory as schema-versioned snapshots. A changed source hash or parser version atomically archives the validated prior snapshot under `.ctxzip-events/versions/` before replacing the latest view. Version paths use the source hash and a parser-version digest; collisions or malformed history are rejected. `resolve_event_reference()` resolves a precise event from retained history or the current view. Existing installations gain historical snapshots as their current versions are next replaced. Events are not yet consumed by retrieval. Changed or deleted Antigravity Markdown files are archived under `raw/antigravity-history/` before the active copy is updated or removed; deleting a current event view first preserves that exact event snapshot in version history. An unreadable/incomplete source inventory aborts reconciliation. If an entire source directory disappears, its archived raw copy and event snapshot remain as historical data.

`capture_git_snapshot()` captures branch/HEAD, staged and unstaged diff hashes, status, changed relative paths, and content hashes for non-ignored untracked files. The worktree fingerprint includes those values so a test run against dirty files differs from a clean commit. It streams diff and untracked-file hashing and does not return diff contents or the absolute repository root.

`test-run` invokes an explicit argv in the target repository without a shell, captures the Git snapshot before execution, and records its result in the selected archive project's private `knowledge/` store. Only the executable basename, exit/result, time, optional repository-relative scope, and pre-run Git identity are persisted; command arguments and process output are not. A failed-to-start command is recorded as an error without inventing an exit code. Tests run outside this wrapper are not intercepted. Context building compares evidence with the current snapshot, so mismatched runs remain historical rather than current.

The `doctor` command runs local diagnostics without creating the archive, contacting an LLM, or printing configured paths and credential values. It reports only whether an API-key environment variable is present. Its source check validates configured root accessibility and the parser/capability/version registry; it does not probe external tool installations or test provider connectivity. Git and the installed CtxZip pre-commit marker are checked read-only. Accepted architecture contracts are indexed in `docs/adr/`; repository contribution checks are in `CONTRIBUTING.md`.

`KnowledgeStore` keeps `tasks.json`, `decisions.json`, `constraints.json`, `test_runs.json`, `open_questions.json`, and `file_mentions.json` under the private project archive's `knowledge/` directory. The directory is ignored and blocked by the staged-content guard. Each collection has a schema version and is atomically replaced; version-1 and version-2 records remain readable and migrate to version 3 when that collection is next written. Decision and constraint validity paths are optional so existing knowledge claims remain freshness-unknown until explicitly scoped. `durum.json` remains dedicated to summary processing. Knowledge claims require event/source-version provenance and an authoring actor. Extractors cannot confirm claims; a user-confirmed decision replacement supersedes the prior decision atomically. Constraint invalidation is narrower: only a user-confirmed replacement in the same scope can invalidate the old record in that atomic write; broader cross-scope conflicts are unresolved. Test records retain a sanitized executable label, result, scope, branch, HEAD, dirty flag, and worktree fingerprint; freshness is derived as current/stale/unknown against a supplied snapshot. The explicit `test-run` CLI command can add evidence for commands it executes; `knowledge add` (Turkish alias: `hafiza add`) adds explicitly user-authored decisions, constraints, tasks, open questions, and file mentions, resolving source references for the selected turn. It requires a granular event snapshot and supports Claude Code, Codex, and ChatGPT; transcript-level Antigravity/manual sources are not selectable through this CLI path. It does not echo claim text or send it to an LLM. Existing records are included in the context planner with source references. The store assumes one writer.

A chapter never crosses a session boundary. The final chunk of an active session is held back. Incomplete chapters are excluded from volumes and context packs. A summary does not replace the source record or the current project state. At summarization startup, the recovery module links recognized orphan Chapters and Volumes into `durum.json` when filename, embedded number, source range, and current state agree; gaps in numbering are allowed and summary bodies are never rewritten. A metadata-less, malformed, contradictory, or source-overlapping orphan blocks summarization and remains untouched. New summaries use the highest persisted number plus one. Volume folding selects only contiguous chapter-number groups, so a missing number is never misrepresented by a volume range.

## Known architectural debt

Critical single-file outputs and source copies use same-directory temporary files and atomic replacement. Fault-injection tests cover summary/state failures, partial collect/transcript batches, and retrying multiple projects after a later project fails; deterministic paths prevent duplicate summary records at those tested boundaries. Sequential and non-sequential orphan Chapters and Volumes with consistent embedded metadata are recovered without rewriting their contents; malformed or ambiguous recognized files block the run unchanged. Subprocess tests also terminate abruptly before atomic replacement, after a Chapter write, and between event/transcript writes; retries preserve readable state without duplicate outputs at those boundaries. Collection-batch and multi-project process termination and retry are covered; power-loss durability, a formal state schema, metadata-less orphan recovery and broader reconciliation remain open. Summary freshness remains unknown when legacy metadata lacks a source hash, a source cannot be parsed, or parser-version metadata is absent. State dictionaries have no formal schema; source discovery/copying, transcript generation, and context-pack generation have moved into core modules behind compatibility wrappers. Automatic knowledge extraction remains disabled; the authoring CLI requires selected-turn provenance and supports only its declared event sources. Granular event adapters for this CLI cover Claude Code, Codex, and ChatGPT; Antigravity/manual inputs provide transcript-level events. Entire source directories removed upstream remain historical in the archive; they are not automatically purged. The knowledge store assumes a single writer. Retrieval and provenance evaluation use synthetic data and are not representative quality evidence. See the [task list](docs/TASKS.md).

Before sending, `call_llm` redacts known secret patterns and previews the full prompt and destination. It makes no network request without interactive approval or the explicit `--approved-send` / `--onayli-gonder` option. For Git safety, `context --copy` / `baglam --kopyala` requires the destination file to be untracked and ignored by the target repository. `scripts/check_staged.py` scans selected index content; `scripts/install_hook.py` installs the check while preserving an existing `pre-commit` hook. These measures are not comprehensive data-loss prevention.
